## Possible cause

**HYPOTHESIS (most likely): a race between the image-cache periodic task and instance deletion.**
1. `_list_backing_images()` walks the instance directories it collected at the start of the pass. It checks whether each `disk` exists, then shells out to `qemu-img info`.
2. In the meantime, the libvirt driver's delete path renames `/var/lib/nova/instances/<uuid>` to `<uuid>_del` and removes it.
3. So the path was valid when the task checked it, but gone when `qemu-img` opened it, which gives ENOENT.
4. `qemu_img_info` turns that into `InvalidDiskInfo`. Nothing in the frames above it catches it, so the whole pass aborts and oslo logs it as "Error during ...".

What supports this:
- In 3 of 3 occurrences I checked, the deleted instance is the one named in the failing disk path.
- In each, "Deletion ... complete" came 18–46 ms before the ERROR.
- The error is rare: 8 tracebacks against 2,064 "Deletion of ... complete" lines (2,064 distinct instances). That fits a narrow timing window, not a systematic fault.

**Likely impact (HYPOTHESIS):** the image-cache pass ends early. Base-file aging and cleanup for that cycle probably don't run, but the instance delete itself completes. Not established by the logs: whether `_base` cleanup was actually skipped. There are no lines after the traceback from req-addc1839 in the window I looked at.

**Alternative A: a storage problem.** For example, instance storage that is unmounted, flaky, or shared (NFS) and losing files.
- How to tell them apart: this would also hit instances that are *not* being deleted, the timing would not line up with DELETE requests, and you would expect errors such as EIO, ESTALE or EACCES rather than only ENOENT.
- What I saw: every occurrence I checked was ENOENT on an instance being deleted, which argues against this.

**Alternative B: something outside nova removed or moved the disk** (a manual cleanup, a script).
- How to tell them apart: there would be no matching "Deleting instance files" line from nova's own delete request just before the error.
- I confirmed nova's own delete was present in 3 of 8 cases; the other 5 are not yet checked.
