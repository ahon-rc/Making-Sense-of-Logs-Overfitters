## Possible cause (HYPOTHESIS)
- **HYPOTHESIS: a race in nova-compute.** The image-cache manager seems to list running instances' disks while an instance is being deleted at the same moment. The delete renames the instance directory to `…_del` and removes it. By the time `qemu-img info` runs on the original `…/disk` path, the file is gone, and nova raises `InvalidDiskInfo` instead of skipping that instance.
  - The timing supports this: the deletion completed 18 ms before the error, and it is a different instance every time.
- **HYPOTHESIS: impact looks limited.** The pass aborts once, the next one succeeds, and the next VM builds fine. The logs don't show whether the aborted pass skipped any cache aging or cleanup that mattered.
- **Unknown:** whether all 8 occurrences line up with a delete in the same way. I only checked the first one.
- **Unknown:** whether the `Unknown base file` / `Removing base or swap file` lines right after the error are related. The cache pass was also removing the base image at 03:19:10, while it was reported as in use by one local instance.

## Next check
1. **NEXT CHECK:** For each of the other 7 timestamps, run `get_context` (±5 s, `service=nova-compute`) and look for `Deletion of /var/lib/nova/instances/<uuid>_del complete` just before the ERROR. If it's there every time, the race hypothesis is confirmed.
2. **NEXT CHECK, code:** in `nova/virt/libvirt/imagecache.py`, look at `_list_backing_images()` (it calls `libvirt_utils.get_disk_backing_file`) and check whether it catches `InvalidDiskInfo` or a missing file for instances being deleted. Compare with the upstream nova bug fixed in later releases, where the image-cache pass skips instances whose disk has disappeared.
3. **NEXT CHECK, config:** look at `image_cache_manager_interval` and `remove_unused_base_images` in `nova.conf` on `cp-1`. In this log the cache pass runs every ~5 s, which is far more often than the default and makes the race much more likely.
4. **NEXT CHECK:** run `trend` with query `InvalidDiskInfo` and `bucket=hour` to see whether the rate follows how often VMs are created and deleted.
